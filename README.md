# atomic-fns

[Read the Docs](https://atomic-stack.github.io/atomic-fns/)

## Like Lodash, but in TypeScript and for ESNext.

Stop shipping code built for browsers from 2015.

You may prefer this library because:

- **TypeScript & docs**: Includes type declaration files and js with JSDocs for best in class experience.
- **Zero deps**: Built from scratch with no runtime dependencies or polyfills.
- **ESNext**: Uses modern idiomatic syntax, data structures, and control flow techniques.
- **Modular**: Pick what you need. Supports tree-shaking, no side effects, and works with all bundlers.
- **Lazy**: Leverage generators, iterators, and functional composition.
- **Tests**: Vitest with v8 coverage thresholds of lines 90, statements 90, functions 90, and branches 85.

## Get Started

This library is available as an [npm package](https://www.npmjs.com/package/atomic-fns).

Requires Node.js >= 24.

```bash
npm install atomic-fns
```

## How to use

Just import any function or class you need.

```js
import { sorted, times, uniqueId } from 'atomic-fns'

;[...times(5, (i) => i)]
// -> [0, 1, 2, 3, 4]

sorted([4, 3, 2, 1])
// -> [1, 2, 3, 4]

uniqueId('user_')
// -> 'user_1'
```

See the full list of [modules](https://atomic-stack.github.io/atomic-fns/modules.html).

## Data model

This library features a data model similar to [Python](https://docs.python.org/3/reference/datamodel.html#special-method-names) but not always. Only the missing parts have been implemented, while respecting the JS standards.

For example, in Python collections, `size()` is a method, while in JS it's just a property. So this library uses `size` property instead of method. Similarly, the `len` function reads `length` or `size` by the same rules as `isEmpty`, since many JS objects have a `length` property.

## Protocol operators

Equality, ordering, arithmetic, cloning, and truthiness dispatch only on exported symbols in `protocol` (for example `protocol.compare`, `protocol.equals`). String method names such as `eq` / `lt` / `compare` on user objects are not called unless you opt in with `adaptProtocol`.

```js
import { adaptProtocol, compare, protocol, sorted } from 'atomic-fns'

class V {
  constructor(n) {
    this.n = n
  }
  compare(o) {
    return this.n - o.n
  }
}
adaptProtocol(V)
compare(new V(2), new V(1)) // 1
sorted([new V(2), new V(1)]).map((v) => v.n) // [1, 2]

const o = {
  [protocol.add](y) {
    return 42
  }
}
```

`eq` is value (numeric/semantic) equality, and `deepEqual` is the same with two differences that make it an equivalence relation: numbers of any kind are equal by exact value, so `deepEqual(1, 1n)` holds while `eq(1, 1n)` does not, and units must match exactly, so `deepEqual(new Currency(5, 'USD'), 5)` is `false` while `eq` says `true`. `compare` is a total order that keeps values of different kinds distinct, like Map keys (the only place unit/kind tie-breaks live). Relational checks - operators `lt`/`lte`/`gt`/`gte`, math `min`/`max`, and Decimal/Currency methods `compare`/`lt`/`lte`/`gt`/`gte` - compare rank-1 values (number, bigint, Decimal, Currency, and anything with a `protocol.unit` string) numerically only: equal amounts of any kind compare equal, so `eq(a, b)` implies `lte(a, b) && gte(a, b)`, with NaN the one exception below. The single remaining difference is the total-order tie-break: `compare(decimal(1), 1) === 1` while every relational check treats them as equal (`decimal(1).lte(1) === true`, `lte(decimal(1), 1) === true`). `new SortedSet([decimal(1)]).has(1) === false` because SortedSet keys use `compare`. Equal-time Dates and IntlDates compare `0`, so `sorted` keeps them stable and `new SortedSet([new Date(0)]).has(new Date(0)) === true`. Arrays order by content (the first 32 elements, two levels deep, then length), before other objects; a content tie between distinct arrays breaks by identity, and typed arrays and other objects order by identity. With a Decimal or Currency on either side, `eq` is numeric equality plus the same unit when both sides carry one, so it is not transitive across units (`USD 5 = 5 = JPY 5`, but `USD 5 != JPY 5`). Between primitives `eq` is SameValueZero, so `eq(1, 1n)` is false while `lte` and `gte` both hold, just as `1 === 1n` is false while `1 <= 1n` and `1 >= 1n` are true. A user class gets `protocol.equals` when it defines it, otherwise `compare(x, y) === 0` when it defines `protocol.compare`. Units come from `protocol.unit` (`Symbol.for('atomic-fns.unit')`). Compare money with money; a plain-number threshold matches any currency (`gte(new Currency(100, 'JPY'), 100) === true`).

Beyond rank-1 values, `lt`/`lte`/`gt`/`gte` go by content and never by identity: Dates by time, arrays by content, strings, booleans and symbols within their kind, wrapper objects as their primitive, and `protocol.compare` hooks by their answer. NaN makes all four false, and so does an Invalid Date against anything but itself. Operands of different kinds, or with no order such as plain objects, are incomparable: `lt` and `gt` are false, and `lte` and `gte` are `eq(x, y)`.

Arithmetic operators call the left operand's hook. When only the right operand has one it runs with `reflected = true` as its second argument, so `sub(1, decimal('3'))` is `-2`. Decimal defines no `protocol.mod` or `protocol.pow`, so `mod` and `pow` throw `TypeError` on a Decimal operand.

## Paths

`get`, `set`, `has`, `del`, `pick`, and `omit` share one path grammar. Dots split (`a.b`) and a segment's trailing numeric brackets walk indexes (`a[0].b`, `m[0][1]`). Quoted and other brackets stay literal, so `a["b"]` is a single key. An array path is the literal form: each segment is a string, number or symbol, so `['a.b']` names the key `a.b`. String paths over 2^20 characters throw `RangeError`.

**Mind the argument order.** `get(key, obj, dflt)`, `set(key, obj, value)` and `del(key, obj)` take the key first, unlike Lodash. `has(obj, key)` takes the object first, as Lodash does. Swapped arguments throw `TypeError`.

```js
get('a[0].b', { a: [{ b: 1 }] }) // 1
set('a.0.b', {}, 1) // { a: [{ b: 1 }] }
has({ 'a.b': 1 }, ['a.b']) // true
del('a.b', { a: { b: 1 } }) // { a: {} }
```

## New Types

[`Decimal`](https://atomic-stack.github.io/atomic-fns/classes/decimal.Decimal.html) provides support for correct rounded floating point arithmetic: exact decimal arithmetic up to 10,000 significant digits (`MAX_DIGITS`) and 10,000 fractional digits of precision (`MAX_PRECISION`). Near the digit cap each operation costs on the order of 0.2 ms, so totals over many attacker-chosen items grow linearly - size-limit untrusted lists.

This fixes precision issues with float arithmetic, for example:

```
0.1 + 0.1 + 0.1
// 0.30000000000000004

decimal('0.1').add('0.1').add('0.1').toNumber()
// 0.3
```

### Signature and behavior notes

- Map-like `set` returns `this`. `uniqueId` returns a string. `hash` returns a number for all inputs and is not value-consistent: `eq(a, b)` does not imply equal hashes. `CustomError(message, options)` forwards `cause`; `name` is the concrete class's name and, like a native error's, not an enumerable key.
- `cache` is a TC39 method decorator. `sorted(it, options)` accepts `{ key, reverse, compare }`. `Decimal.div(x, opts)` takes `{ precision, rounding }`. `Deque(items, { maxlen, arrType })`.
- `remove(arr, pred)` mutates and returns removed elements (Lodash), and any other non-nullish value throws `TypeError('remove expects an array')`. Prefer `without(arr, ...values)` for the old pure value form; `reject` is the pure predicate form and passes the real key or index, as `filter` does.
- Iteratees: in every helper that takes one, `count` and `groupBy` included, a missing or null iteratee is identity, `[path, value]` tests that path as `matches` would, any other object is a `matches` shape, and a key reads that path. `find` / `findLast` take `fromIndex`. Search starts follow `ToIntegerOrInfinity`, and a negative start counts from the end on both sides. `count` and `groupBy` return null-prototype objects, as `Object.groupBy` does; a key too deep to stringify throws `RangeError('nesting deeper than 1000 levels')`.
- List input: the search helpers (`findIndex`, `indexOf`, `findLastIndex`, `lastIndexOf`) and the set-style helpers (`uniq`, `sortedUniq`, `union`, `difference`, `intersection`, `symmetricDifference`, `without`) read nullish input as empty and accept iterables and array-likes; a value that is neither finds nothing. An array-like counts only when its own index keys back its `length` (the huge sparse rule, at any size), so a bare `{ length: 1e9 }` is empty. `symmetricDifference` takes any number of inputs and keeps what exactly one holds, as `_.xor` does. `compact` gives `[]` for nullish and an array for strings, iterables, and array-likes; a plain object, or any other object, compacts into a new plain object. `flatten` gives `[]` for nullish, spreads strings and array-likes, flattens a plain object as an object even with a `length` key, and returns any other value unchanged.
- Array holes: a helper named after a native Array method follows it, so `indexOf` / `lastIndexOf` / `filter` / `forEach` skip holes, `map` keeps them, and `find` / `findIndex` / `findLast` / `findLastIndex` visit each one as `undefined`. `forEachRight`, `reject`, and `count` follow `forEach` and `filter`. The set-style helpers read a hole as `undefined`, as `new Set(arr)` does. `remove` shows its predicate a hole as `undefined`, removes a matched hole, and keeps the offset of the others, as Lodash does. Exception: a huge sparse array (length above 2\*\*24 and mostly holes) costs own-element time, so the set-style helpers and `remove` skip its holes and the `find` family sees each hole run once.
- `compare` is a total order across kinds; `eq` is semantic equality (see Protocol operators). Decimal compare/equals with numbers uses exact binary values (`decimal('0.1').eq(0.1) === false`). A number enters `decimal()` through its shortest round-trip string, so `decimal(0.1).eq(0.1) === false` too, unlike Python's exact `Decimal(0.1)`. Decimal `eq` is `false` for anything unparsable (`decimal(1).eq(null)`); `compare`, `lt`, `lte`, `gt`, and `gte` throw on it.
- Decimal bounds are all 10,000 and read-only: `MAX_EXPONENT` (stored `|e| <= 10000`), `MAX_PRECISION` for `div` / `sqrt` / `round` (round also accepts down to `-MAX_EXPONENT`), and `MAX_DIGITS` significant digits. They bind results, after rounding: constructor, parse, and arithmetic throw `RangeError('result exceeds 10000 digits')` past `MAX_DIGITS` and `ValueError('exponent out of range')` past `MAX_EXPONENT`. `div` and `sqrt` always round to `precision` fractional digits (default 20), so `decimal('1e-30').div(1)` is `0` until `precision` reaches 30, where Python's `Decimal` keeps significant digits. An unknown rounding mode throws `RangeError`. `toNumber` returns the nearest double, read from coefficient and exponent (never via a full plain string).
- Decimal `toString` and `toJSON` use plain notation while that pads at most 64 zeros (after an integer's digits, or between the point and a fraction's first digit), and scientific form past that (`1e+65`, `1.5e-70`), as decimal.js and big.js do, so output length follows the significant digits and not the exponent. `decimal()` parses both forms back. `toPlainString()` always expands, up to 20,000 characters.
- math `round` coerces other values with `Number` as `Math.round` does, and a Decimal rounds exactly and stays a Decimal. `min` / `max` skip `null`, `undefined`, and `NaN` as Lodash does (after `key`, which runs once per item), keep the `compare` order across mixed kinds, compare arrays by content (`min([[1], [2]])` is `[1]`), and order plain objects by first-seen identity. `sum` adds numbers natively and folds anything else with the `add` operator from the first item, so Decimals stay exact, bigints work, and strings concatenate; `mean` coerces with `Number`, so a Decimal needs `key`. `sum` calls `key` for every hole and refuses huge sparse arrays like `min`, `max`, and `mean`. `abs` takes bigint. `divmod` follows Python: exact remainder with the sign of the divisor, `ZeroDivisionError` for a zero divisor.
- `random(max)` means `[0, max)`. `random` needs finite bounds and `randomInt` safe integers, else `RangeError`, and both reject `max < min`. `randomInt` is uniform across any span. `choice`, `sample`, and `shuffle` all take an array, any iterable, or a plain object (its values); anything else has no items. `sample` requires an integer `k` and returns `[]` for a negative one.
- `range(NaN)` throws. `uuid` throws without Web Crypto. `difference` is set difference. Decimal `valueOf` throws.
- `formatDate` tokens are maximal runs of one ASCII letter (plus `Do` / `LT` / `LTS`), so `Month` reads as `M`, `o`, `n`, `t`, `h`; unknown runs stay literal as a whole. `YYYY` / strftime `%Y` zero-pad to 4 digits (`0050`, `-0001`); `YY` / `%y` are `|year| % 100` zero-padded to 2. The default pattern uses signed 6-digit years outside 0-9999 (`+275760-09-13T00:00:00+00:00`) so `asDate` reads them back. Numeric tokens and month and era names are Gregorian in every locale. `MMMM` takes the form the locale uses next to a day when the pattern has `D`, `DD`, or `Do` (`31 октября`), and the standalone form otherwise. `LT`, `LTS`, `a`, `A`, `%p`, `%P`, and the `L` / `l` presets follow the locale and its hour cycle. `Z`, `ZZ`, and `%z` add seconds for offsets that have them (`-04:56:02`). `strftime` supports `%%` -> `%`; unknown directives stay literal. `%k` is the hour 0-23, space-padded. `%n` is a newline, as in every strftime; the era is `N` in `formatDate`, and `%N` (long) in `strftime`. A locale argument is a tag, an `Intl.Locale`, or a list of them, and only plain objects are options. An invalid tag throws `RangeError` whatever the tokens, and so does a locale past 255 characters, in `Duration.format` and `Currency` too. Formatter cache is a capacity-64 LRU.
- `IntlDate.set` and `new IntlDate({...})` accept only `DateObject` field names (singular or plural) with integer values. Unknown units and other values throw `ValueError`, also on an invalid receiver. Keys that 1.x silently ignored via `UNITS_SINGULAR` (`weeknumber`, `weekyear`, `ordinal`, `quarter`, and their plurals) now throw. `weekday` (1 = Monday) moves within the ISO week. Setting a field inside a repeated local hour keeps the receiver's offset when that offset remains valid.
- `new IntlDate(value)`: only `undefined` means now; any other value that is not date-like (booleans, arrays, Maps) is invalid. A `Date` from another realm keeps its instant. Copying an `IntlDate` keeps its `locale` and `utc` unless the options replace them; `clone(null)` is invalid. `JSON.stringify` writes the ISO string, or `null` when invalid (`toJSON`). `toISODate` / `toISOTime` split expanded years (`-000001-06-15`).
- `IntlDate.add` / `subtract` / `set` / `startOf` / `endOf`: results outside the Date range throw `RangeError`. In `add` / `subtract`, calendar fields advance the wall date once (month-end constrain), then time fields add exact milliseconds; unknown or non-finite duration fields throw `ValueError`.
- `IntlDate.diff` follows Temporal: whole units are `until` with `smallestUnit: unit`, `roundingMode: 'trunc'` (calendar-correct years/quarters/months/weeks/days, so the count never passes the end instant across a DST gap or repeated hour), and `exact` is the `total` of the elapsed time. `isBefore` / `isAfter` / `isBetween` read strings and objects in the receiver's view, as `diff` does.
- `IntlDate.from` / `to` / `fromNow` / `toNow`: omitting the unit picks the largest of years, months, days, hours, minutes, seconds with absolute count at least 1; a zero count uses `Intl.RelativeTimeFormat` `numeric: "auto"` ("today", "now", ...). `a.to(b)` is `b.from(a)`. An invalid date on either side gives `"Invalid Date"`.
- `IntlDate.min` / `IntlDate.max` take one `readonly DateLike[]` (no varargs; anything but an array throws `TypeError`, as in `minDate` / `maxDate`); empty or all-invalid still returns `undefined`. `minDate` / `maxDate` ignore numbers outside the Date range.
- `weekOfYear(date, firstDay = 1, minimalDays = 4, utc)` and `weeksInYear(year, firstDay = 1, minimalDays = 4)` use CLDR week rules (ISO by default). The third parameter is `minimalDays` (1..7), not a day-of-year threshold. `IntlDate.week()` / `weekYear()` / `weeksInYear()` follow the instance locale (`Intl.Locale` week info, with a CLDR `minimalDays` fallback table because engines do not yet expose `minimalDays`); `isoWeek()` / `isoWeekYear()` / `isoWeeksInYear()` are ISO 8601. A `-u-rg-` override also picks the `minimalDays` region. `startOf('week')` uses the locale first day; `startOf('isoWeek')` is Monday. Day-or-larger `startOf` / `endOf` use compatible wall resolution, and `endOf` ends 1 ms before the next unit starts; hour/minute/second keep the receiver's offset when valid. `weeksInYear(year)` needs a safe integer year.
- `asDate` trims strings, then parses the ISO-8601 / ECMA-262 Date Time String format, also accepting one-digit months and days, `YYYY-Mon-DD` with an English month abbreviation, and offsets with seconds (`-04:56:02`, `-045602`), so `asDate` reads back what `formatDate` prints for historic zones: out-of-range fields are invalid, the 4-digit years `0000`-`0099` are literal, and date-only and zone-less strings use local wall time (unless `utc`). Any other text after a signed year, a `YYYY-M` date or a time is invalid, except meridiem and zone tokens after a time (`10:00 PM`, `10:00:00 UTC`, `10:00:00 +0000`), which go to engine parsing. Other non-ISO strings also go to engine parsing, so two-digit years there follow the engine and `utc` does not apply; non-ISO strings longer than 128 characters are invalid.
- `Duration` is frozen and exact at 1 ns (`bigint`), and a field reads as its shortest decimal (`{ years: 1.1 }` is 1.1 years, not its binary expansion). `add` and `subtract` sum field by field in doubles, so a sum past 2^53 rounds and signs can mix (`{ hours: 1 }` minus `{ minutes: 30 }` is `{ hours: 1, minutes: -30 }`). Calendar units share one year length (365-day year, or mean Gregorian 365.2425 d in exact mode) so 1 year = 4 quarters = 12 months. Constructor inputs are finite numbers under the nine plural field names of a plain object (else `ValueError`, also for `Date`, `Map`, and class instances); `Duration.from`, `add`, and `subtract` also reject `undefined`. A Duration from another copy of the library is read through the `Symbol.for('atomic-fns.duration')` brand. ISO strings go through `Duration.from` (Temporal-style grammar: leading sign only, ASCII case-insensitive, `.`/`,`, fraction only on the last time component, <= 9 digits, components <= `MAX_SAFE_INTEGER`). Components stay as written (`PT1.5H` is `{ hours: 1.5 }`); a fraction a double cannot carry to 1 ns keeps its whole part and spills into `milliseconds`. `round` follows Temporal with fixed unit lengths: it rounds to `smallestUnit` by `roundingMode` (default `halfExpand`), a string means `smallestUnit`, and `largestUnit` defaults to the largest non-zero field or `smallestUnit` when larger. Without `smallestUnit` it only rebalances. Weeks appear only when `largestUnit` or `smallestUnit` names them, otherwise that time folds into days. `toISOString` uses one leading sign, normalizes mixed signs, keeps only seconds fractional, and prints `PT0S` for anything that rounds to 0 ns. `format` and `abs` normalize mixed signs too. Zero `format` is `0 sec`. `format` returns `toISOString()` where `Intl.DurationFormat` is missing or a value is past its range. `eq`, `compare`, `lt`, and `deepEqual` compare total length. `toJSON` is `toISOString`, `toLocaleString` is `format`, and `valueOf` throws, as on Temporal. `durationField(unit)` replaces `UNITS_PLURAL`.
- `Currency` display keeps the amount's digits, up to 20 fraction digits, instead of rounding to the currency's minor unit (`¥1.5`, `$0.30000000000000004`); `1e-21` dollars show `$0.00` though the amount stays exact. `maximumFractionDigits`, significant digits, `roundingIncrement`, or a non-standard `notation` hand the display to `Intl.NumberFormat`, and `precision()` uses the currency's own digits. `round` and `sqrt` keep the unit. `round` defaults to half-even while `precision` displays half-expand: `0.125` rounds to `0.12` and shows as `$0.13`. In `format`, overriding one of `minimumFractionDigits` / `maximumFractionDigits` drops the instance's other.
- `matches` follows Lodash `isMatch`, apart from the rows in [Coming from Lodash](#coming-from-lodash): a top-level empty `{}` / `[]` matches any value; a nested empty `{}` matches any non-null non-array object and a nested empty `[]` matches any array; arrays in the shape are subsets, and each target element serves at most one shape element, claimed greedily in order, so `matches([1, 1])([1, 2])` is `false`; a hole reads as `undefined`; a top-level plain-object shape boxes its target, so `filter(['abc'], { length: 3 })` keeps the string, and below the top level it never matches an array; shape keys read `target[key]`, so inherited and non-enumerable keys match, while `{ a: undefined }` requires own key `a`; a primitive shape compares with `eq`; Date/RegExp/Map/Set/typed-array and class-instance shape values use deep equality (not reference). Nesting past 1000 levels throws `RangeError`.
- `deepEqual`, `clone` (deep), `merge`, `flatten`, and `omit` along a path also throw `RangeError` past 1000 levels of nesting (security bound). Collection `protocol.equals` / `protocol.clone` hops charge 8 levels each (`HOOK_NESTING_COST`), so self-nested collections are capped at 125 levels (1000 / 8) before the same `RangeError` - enough that the native stack still has headroom when the counter fires.
- `deepEqual` compares each shared object once, so time and memory stay proportional to the distinct objects however they share, and cycles of different lengths compare in the sum of their lengths: rings of 31 and 37 identical nodes are equal. It remembers at most 2^20 failed comparisons per call. A `protocol.equals` hook must be an equivalence relation. A `deepEqual` called from a getter, or from user code inside a `clone`, starts its own session; one called from a `protocol.equals` hook shares the walk's.
- `deepEqual` dispatches on internal slots, never `instanceof`: equal values from another realm are equal, as in Lodash `isEqual`, while in one realm a subclass instance never equals a base instance. Kinds it does not know (URL, URLSearchParams, Headers, Blob, Promise, WeakMap, WeakSet, WeakRef, generators, iterators, objects with their own `Symbol.toStringTag`) equal only themselves. Errors compare `name` and `message`, SharedArrayBuffers compare bytes, float typed arrays compare elements by SameValueZero (`0` equals `-0`, `NaN` equals `NaN`), and invalid Dates equal each other. Own enumerable symbol keys count, non-enumerable keys do not. Null-prototype and `Object.prototype` objects are one plain kind, and `arguments` compares like a plain object, as in Lodash. An explicit `undefined` equals an array hole at every size. Prototype-only objects such as `Object.create(Date.prototype)` and detached views no longer throw. `shallowEqual` shares the plain-kind and realm rules, takes `NaN` as equal to itself, and compares other builtins (Date, Map, Set, ...) by identity.
- `clone` copies Node `Buffer`s and own enumerable symbol keys; `DataView` keeps offset/length over a full buffer copy; deep `Map` keeps key identity and deep-clones values; RegExp match arrays keep `index`/`input`/`groups`; a Date keeps its own enumerable keys; class instances stay by reference, subclasses of Map, Set, Date, RegExp, Array and the other builtins included, as does an object whose `Symbol.toStringTag` claims a builtin it is not. Plain objects, arrays, and builtins from another realm are copied. `clone(collection, true)` passes `deep` to `protocol.clone`: map-like collections keep keys by reference and deep-clone values; set-like deep-clone values. One deep `clone` call copies each object once, also through `protocol.clone` hooks, so references shared inside a collection stay shared in the copy, as they do in arrays: `clone(new Deque([row, row]), true)` holds one copy of `row`. A collection in a cycle keeps the cycle, as arrays and native `Map` do: after `m.set('self', m)`, `clone(m, true).get('self')` is the copy itself. A deep clone builds an empty copy with `cloneFrom([])` and fills it, through `set` on a `MapCollection` and through the abstract `cloneInsert` on a `SetCollection`. Collection equality is order-independent for set-like (FrozenSet, Trie) and map-like (LRUCache) types, multiset for Heap (deepEqual multiset, comparator-independent), and sequence for Deque/SortedMap/SortedSet/BTree/SplayTree. `clone` of a subclass of these collections builds it through its own constructor with the base class's arguments; a subclass with another signature overrides `cloneFrom`.
- `deepEqual` compares Set members, and the entries of a Map with an object key, as multisets under `deepEqual`, as Lodash `isEqual` does: `deepEqual(new Set([{ a: 1 }]), new Set([{ a: 1 }]))` is `true`, and FrozenSet and LRUCache follow. Heap, Set and Map share one matching: identical values and references cancel, the rest pair within groups of a bounded structural hash, and the answer is exact. Items no bounded hash can tell apart pair all-to-all, so a huge list of them throws `RangeError('deepEqual exceeded 33554432 comparisons')`; so does a list past a few thousand items that carry a hook with no numeric value in a field, in different orders. Rank-1 values such as Decimal hash by their `Number` and date-like ones by their time, so they bucket like numbers and Dates. A Set, or a Map with an object key, charges like a collection hop, so one nested in itself stops near 200 levels, and an LRUCache nested in its own keys near 75.
- `Heap.push` takes several items. `new Heap(null)` and a `null` comparator mean omitted. `Heap.delete` leaves the heap unchanged when the comparator throws. `heapify`, `insort` and `insortLeft` throw `RangeError('sparse array too large')` on huge sparse arrays.
- `Deque` reads an iterable one item at a time, so `new Deque(lines, { maxlen: 10 })` holds at most 10 of them. `maxlen: null` means unbounded. `at` and `set` coerce an index as `Array.prototype.at` does, so `set(undefined, x)` writes index 0. `clear` gives back the capacity of a burst.
- `bisect`, `bisectLeft`, `binarySearch`, `insort` and `insortLeft` throw `TypeError` for a `lo` or a finite `hi` that is not an integer, as Python does; `null` and `undefined` `hi` mean the length.
- `LRUCache` iterators and `forEach` walk a snapshot taken when they start, so `get` and `set` inside a loop are safe, and an entry added during the loop is not visited.
- `SplayTree` `lower` and `higher` splay the node they return, and an iterator that finds the tree restructured splays its next key, so iterating reshapes the tree. With `p = 0` reads never reshape it, so they lose the amortized bound.
- `Trie` is path-compressed, so memory grows with the number of words. `matches` takes `null` for no limit and throws `TypeError` for a limit that is `NaN` or not a number. `new Trie(0)` throws `TypeError`, as any non-iterable does. `clear` ends running iterators, and a word added during iteration may be skipped.
- `merge` copies own enumerable symbol keys and writes by assignment, so target setters run as in `_.merge`. Nullish and scalar sources are skipped; a nullish, scalar, or function target throws `TypeError('merge target must be an object')`. An undefined source value is skipped when the key is in the target, own or inherited. When a path's target and source containers differ in kind (array vs plain object), the source replaces the target. Each key gets its own copy of a shared source (cycle protection is path-scoped only); expanding a source again costs one work unit per 16 keys, plus one once repeats outnumber the input's keys, on a cycle as on a shared row, and past 500,000 units it throws `RangeError('input repeats shared objects beyond 500000 copied nodes')`. `matches` remembers up to 2^20 (shape, value) pairs and stops at 2^25 comparisons (`RangeError('matches exceeded 33554432 comparisons')`), so its memory and time stay bounded on any input. `flatten` has its own lower cap of 250,000 units, counting only what `depth` reaches (`RangeError('input repeats shared objects beyond 250000 containers')`). It throws `ValueError('cyclic structure')` on a cycle within `depth`, and `RangeError` past 2^27 characters of output keys, a key over 16383 characters counting 16 times (longer keys hash by length alone in V8, so inserting them is quadratic).
- `pick` / `omit` take one path, a list or `Set` of paths, or a predicate; a path is a string (the shared grammar, see Paths), a number or symbol key, or an array of literal segments (`[['a.b']]`). Anything else throws `TypeError('path segments must be strings, numbers or symbols')`. `pick` reads own properties only, and mirrors array vs object containers from the source when the next segment is an index. `omit` is O(keys + paths), never invokes getters of omitted keys; kept data values use a normal `[[Get]]` (symbol keys are not copied). Top-level input and every descended container must be a plain object or plain array (prototype `Object.prototype`/`null`/`Array.prototype`) without a callable or accessor `toJSON`; class instances, Array subclasses, Maps, Dates, collections, functions, and values with a function/accessor `toJSON` throw `TypeError` (fail closed). A data `toJSON` holding a non-function is ordinary data. Values not on a path stay by reference.
- `Decimal` and `Currency` are false at zero, `Duration` at zero length, and collections when empty, through `protocol.bool`, as in Python: `bool(decimal('0'))`, `bool(new Deque())`, `all([decimal('0')])` and `any([new Deque()])` are false. `compact` and `icompact` still keep a zero `Decimal`.
- `isEmpty` honors a `protocol.bool` hook, so `isEmpty(decimal('0'))` is true like `isEmpty(0)` and `isEmpty(decimal('5'))` is false, and wrapper objects count as their primitive. `isEmpty(fn)` ignores arity; a function is empty unless it has own enumerable properties. Length applies only to arrays, strings, arguments, typed arrays/Buffers, and splice-able objects; byte length to ArrayBuffers and DataViews; size only to Map/Set and a `size` a class defines on its prototype. Objects that merely own a `length` or `size` key count own keys (not empty when other keys exist). `len` follows the same rules.
- `uniq` / `without` / `intersection` normalize `-0` to `+0` in results (native Set semantics).
- `defaults` fills keys whose own value is `undefined`, or that are missing as own and equal `Object.prototype[key]` (e.g. plain `toString`); inherited class getters/methods are never overridden. Writes use assignment (setters run) except `__proto__` (defineProperty, null-prototype targets only). Nullish sources are skipped; a nullish or scalar target throws `TypeError('defaults target must be an object')`.
- `isPlainObject` needs the tag `[object Object]` and a `null` or `Object.prototype` prototype of any realm, so `Math`, `JSON`, and `arguments` are not plain. `defineData` always defines an own data property; it never runs a setter.
- `words` uses `Intl.Segmenter` word granularity plus Unicode letter/digit, ordinal (`11th`), plural-acronym (`IDs`), and RGI emoji rules; an optional `pattern` is a separator. Characters the segmenter calls non-word-like still count when they are letters or numbers (`words('CO₂')` is `['CO', '₂']`), and a word glued to an emoji by ZWJ splits from it. ASCII input takes a fast path; other input costs about 15x Lodash on short strings. `camelCase` / `pascalCase` / `snakeCase` / `kebabCase` strip apostrophes, keep accents, and uppercase with `toUpperCase` (so `pascalCase('ǆemal')` is `Ǆemal`). `titleCase` applies the Unicode titlecase mapping to the first letter of each word (rest unchanged, `ß` -> `Ss`). `capitalize` lowercases the string, then applies the titlecase mapping to its first code point (`ǆ` -> `ǅ`). `removeAccents` / `slugify` follow a subset of the Unicode CLDR Latin-ASCII transform (NFD, strip Mn after Latin letters or ASCII digits, NFC, then common letter folds; `ƒ`, `ǆ`, `©`, and fullwidth forms stay). Non-Latin marks are kept, and a run of marks is cut to 30, the UAX #15 limit that keeps normalization linear.
- String input follows Lodash: `null` and `undefined` become `''`, and other values go through `String`. `words(s, null)` means no pattern. `isAlnum` / `isAlpha` / `isNumeric` are `false` for non-strings. `isNumeric` tests `\p{N}`, so CJK numerals such as `'一'` are `false`, unlike Python `isnumeric`.
- `debounce` and `throttle` take Lodash `leading` and `trailing` options. `wait` defaults to 0, a null `maxWait` is absent, and errors name the parameter. `debounce` measures `maxWait` from the first pending call. `throttle` uses Lodash leading+trailing defaults (latest args at window end), and `throttle(fn, 0)` is leading plus one trailing per macrotask. Its window opens before `fn` runs, so a reentrant call, a throw from `fn`, and a call right after `flush` all stay throttled, and a call just after a trailing edge waits for the next one (Lodash can fire at once there).
- Function wrappers (`curry`, `partial`, `flow`, `compose`, `memoize`, `cache`, `debounce`, `throttle`, `once`, `result`, `resultAsync`, `promisify`) throw `TypeError('Expected a function')` at creation. `curry(fn, arity)` takes an arity and runs with the latest `this`. `flow()` and `compose()` return their first argument, and arrays of functions flatten one level. `memoize` exposes `.cache`, which lookups read and which may be replaced, and `.clear()`, and calls `resolver` with `this`. Its cache and each `cache` store grow without eviction; past the engine's `Map` limit, new results are returned but not remembered. `cache` runs uncached on a non-object `this`. `once` never retries: a reentrant call or any call after a throw returns `undefined`. `result` and `resultAsync` turn a thrown `undefined` into an `Error`. `promisify` treats a falsy `err` as success and forwards `this`.
- Iterator helpers read an array like `[...arr]`, so each hole is `undefined`. `reduce` follows `Array.prototype.reduce` instead: it skips holes and passes real indices. A huge sparse array throws `RangeError('sparse array too large')`, except in `all`, `any`, `contains`, `first`, `icompact`, and `reduce`, which walk own elements; a hole run costs `all` and `any` one predicate call. `first`, `take`, `itake`, and `islice` with a `stop` close a passed iterator, as the native `take` does, so a generator is spent afterwards. `reversed` reads an iterator to its end first. `accumulate`, `chain`, `iflatten`, `takeWhile`, and `zip` return plain iterators, not generators, and close their sources even on a `return()` before the first `next()`; an error in flight outranks a failing `return()`.
- `range`, `zip`, `chain`, `accumulate`, and `takeWhile` validate at the call. `islice` follows Python: `islice(it, stop)` or `islice(it, start, stop, step)`, `null` means the default, a `start` past `stop` is empty, and a non-integer argument throws `ValueError`. `range` throws `RangeError` for a non-number or a non-finite `start` or `step`; `stop = Infinity` stays lazy. `times` truncates `n`, defaults `fn` to identity, and `times(Infinity)` is a lazy infinite generator. `take(undefined, it)` takes 1, and a negative count is empty. `flatMap` flattens a non-string iterable result and yields anything else as is. `contains` is `false` for a RegExp in a string and checks a `Map`'s keys. `iter` throws `TypeError` for a value that is neither iterable nor an object. `accumulate` reads an `undefined` initial as absent. `sorted(it, null, true)` still reverses.
- `compare` fast-paths same-type non-NaN numbers and strings; total order unchanged.
- `BTree` is a copy-on-write order-statistic B+ tree: `clone()` is O(1) until either side writes; a non-finite comparator result throws `TypeError('comparator must return a finite number')` and leaves the tree unchanged; every new key must compare 0 with itself, else `TypeError('comparator must return 0 for a key compared with itself')`, so `(a, b) => (a < b ? -1 : 1)` is rejected; comparators must be pure; `setAll` / `removeAll` / `removeRange` / `updateRange` are atomic, `freeze()` during one of them throws `TypeError`, and `setAll` reads its whole input before the first write; under a strict total order, iteration under mutation never repeats a key, and it ends unless the loop keeps inserting keys ahead of the cursor, as with native `Map`; `at(index)` is O(log n) with Array.prototype.at index rules; `nodeCapacity` is an integer in 8..1024 (default 64, else `RangeError`); `freeze()` is one-way; `removeAll` throws `RangeError('sparse array too large')` on huge sparse arrays. Numeric subtraction comparators reject `Infinity` / `NaN` keys and finite keys whose difference overflows (those differences are not finite) - use the default `compare` when those keys matter. The constructor and `setAll` on an empty tree bulk-load without calling `set`, so a subclass override of `set` runs only for `setAll` on a non-empty tree.
- BTree 1.x call shapes: `includeHigh` and `maxLength` moved to `options` (`{ inclusiveEnd, limit }`), `visitRange` / `updateRange` take their callback third, and the constructor's third argument is `{ nodeCapacity }`; a non-object `options` throws `TypeError('options must be an object')`. `keys(firstKey)` / `values(firstKey)` lost the start key; use `entries(from)`. `entries` / `entriesDescending` treat `undefined` as omitted, also in a tree with an `undefined` key. Under the default `compare`, an omitted `to` in `removeRange` / `entriesBetween` means up to the end: `undefined` ranks last, and an `undefined` key itself needs `inclusiveEnd`. `updateRange` callbacks may return `null` like `undefined`, a falsy `remove` leaves the entry alone, and a primitive throws `TypeError`.
- `BTree`, `SortedMap`, and `SortedSet` constructors follow native `Map` / `Set` input rules: `null` means empty, a non-iterable throws, and an entry must be an object (`new BTree([1, 2])` throws `TypeError('entries must be [key, value] pairs')`). A non-function comparator throws `TypeError('comparator must be a function')` at construction. `clone` keeps the subclass of all three by calling its constructor with `(entries, compareFn)`, plus `{ nodeCapacity }` for `BTree`; a subclass with another signature overrides `cloneFrom`. `SortedMap` and `SortedSet` store `-0` as `+0`, as native `Map` and `Set` do, expose `isFrozen`, and name themselves in the frozen error (`TypeError('SortedMap is frozen')`); `add` of an existing value on a frozen `SortedSet` throws too. `SortedMap.get(key, defaultValue)` matches `BTree.get`. `new SortedSet` keeps plain objects and arrays, which order by identity, in first-seen order as `add` does, so a deep clone keeps the sequence.

## Releasing

One-time owner setup (must complete before any 2.0 release), in this order:

1. Create a GitHub environment named `npm` with a required reviewer and a deployment rule of type `tag` matching `v*` only (no branch rules). Confirm both the required reviewer and the tag rule show on the environment page. GitHub auto-creates a referenced environment with no protection, so this step must precede any release.
2. Create a repository ruleset that restricts who can create `v*` tags.
3. On npm, bind a trusted publisher to this repository, workflow `publish.yml`, environment `npm`.
4. Once this branch is merged to main and no workflow on main references `NPM_TOKEN`, delete the repository secret `NPM_TOKEN`, revoke that npm token, and set the package to "Require two-factor authentication and disallow tokens", all before creating the first 2.0 release (a failed trusted publish fails safely and can be retried).
